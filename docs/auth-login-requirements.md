# 登录与钱包「auth」· 产品需求说明

> 按真实产品语义撰写；不含演示数值。
> 实现：`auth.js`（全站注入）+ `mobile-login.html`（移动端登录页）；账户面由 `load-desktop-header.js` 渲染。
> 阅读建议：先读 §1（登录方式）与 §2（内嵌钱包与地址），再看 §3 各页面表现。

---

## 0. 页面定位与用户故事

- **定位**：全站身份入口。登录即产出「账号 + 链上钱包」一体身份：邮箱/社交登录由平台创建**内嵌钱包**，外部钱包则直接连接；此后发射、交易、资产等 Web3 能力都以该钱包为身份。
- **用户故事**
  - 作为新用户，我用邮箱验证码或 Google / X 登录，无需安装钱包插件即可获得一个链上钱包。
  - 作为已有钱包的用户，我可以在钱包列表里选择钱包并签名连接。
  - 作为已登录用户，我在顶栏能看到自己的脱敏地址、可复制全量地址，并能随时退出登录。

---

## 1. 登录方式与流程

登录弹窗（`openLoginModal()`）提供四个入口，统一由 `finishLogin(method, opts)` 收口。

| 方式 | 步骤 | `authMethod` | 完成文案 |
|---|---|---|---|
| 邮箱登录 | ① 输入邮箱 →「发送验证码」② 输入 6 位验证码 →「验证并登录」 | `email` | 已通过邮箱登录 · 已创建内嵌钱包 `{脱敏地址}` |
| Google | 一步完成（模拟授权） | `google` | 已通过 Google 登录 · 已创建内嵌钱包 `{脱敏地址}` |
| X (Twitter) | 一步完成（模拟授权） | `twitter` | 已通过 X (Twitter) 登录 · 已创建内嵌钱包 `{脱敏地址}` |
| 连接钱包 | ① 选择钱包（MetaMask / WalletConnect / Coinbase Wallet）② 签名确认 | `wallet` | 已连接 `{钱包名}` · `{脱敏地址}` |

### 1.1 邮箱两步
- 邮箱校验：`邮箱@域名` 基本格式，非法时行内红字「请输入有效的邮箱地址」，不进入第二步。
- 发送成功后：第一步隐藏、第二步展示，验证码框自动聚焦并清空；toast「验证码已发送（演示：123456）」。
- **重发倒计时**：重发按钮 60 秒内禁用并显示「重新发送（{n}s）」，归零后恢复为「重新发送验证码」；点击重发重置倒计时并 toast。
- 验证码校验：必须 6 位数字，否则行内「请输入 6 位数字验证码」；与演示码不一致则行内「验证码不正确，请重新输入」，**不进入登录态**。
- 通过后按钮进入 busy（其余按钮禁用），约 0.7s 后完成登录。

### 1.2 外部钱包
- 钱包列表：MetaMask（浏览器扩展）/ WalletConnect（扫码连接）/ Coinbase Wallet（移动端 App），逐项可点。
- 签名确认弹窗：展示请求方（Story.fun 想要连接你的钱包）、签名性质说明（仅身份验证、不产生链上交易、不收费）与当前脱敏地址；提供「拒绝」与「签名并连接」。
  - 「拒绝」→ 关闭弹窗 + toast「已取消钱包连接」，保持在未登录态。
  - 「签名并连接」→ 按钮依次显示「等待钱包确认…」，约 0.9s 后完成登录并记录所选钱包名。

### 1.3 弹窗通用
- 底部固定一行「由 Privy 提供（模拟）」；末尾附服务条款 / 隐私政策链接。
- 关闭：右上 ✕ / 点击遮罩；关闭弹窗时清理倒计时定时器。
- 已登录用户点击登录入口：不弹登录框，直接展开账户下拉。

## 2. 内嵌钱包与地址（单一来源）

- 地址由 `window.currentWallet` **统一提供**，按账号 id 确定性派生：**同一账号永远同一串地址**，换账号即变化。
- 两个形态：
  - `address()`：40 位全量地址（用于复制、详情展示）；
  - `masked()`：`0x1234…abcd`（用于顶栏胶囊等紧凑位）。
- **全站唯一**：以下位置必须取同一来源，禁止各自派生（历史遗留的三套哈希已收敛）：

| 位置 | 展示形态 |
|---|---|
| 顶栏账户胶囊 | `masked()` |
| 顶栏账户下拉 | `masked()` + 「复制」（复制 `address()` 全量） |
| 资产页身份 hero | 截断显示 `masked()`，`title` 与「复制」为 `address()` |
| 发射页创建者钱包占位 | `masked()` |
| 持仓分享卡 | 不展示地址（保持 pons 版式） |

- 引擎 `Launch.walletText()` 亦取该来源，作为兜底保留本地派生（未加载 `auth.js` 的页面不报错）。

## 3. 登录态与各页面表现

- **初始状态**：本地无登录存档时即为**未登录**（不预设"默认已连接钱包"），顶栏显示「登录 / 注册」，发射台页面按各自规则拦截。
- **状态广播**：登录与退出都会派发 `auth-ready`（带 `bubbles: true`），`document` 与 `window` 上的监听均可收到；同时主动刷新账户面（`.auth-container` 与顶栏胶囊）。

| 场景 | 顶栏账户胶囊 | 页面行为 |
|---|---|---|
| 未登录 | 显示「登录 / 注册」，点击打开登录弹窗 | 发射台页面按各自规则拦截：创建 / 交易 / 充值提现 / 领取收益 → 弹登录引导 |
| 已登录（邮箱或社交） | 头像 + `masked()`；下拉显示「{登录方式} · {邮箱}」+ 地址行 | 完整可用 |
| 已登录（外部钱包） | 头像 + `masked()`；下拉显示「外部钱包」+ 地址行 | 完整可用 |
| 访客态（`assets.html?address=0x…`） | 显示「登录 / 注册」 | 资产页只读展示所查地址，资金操作统一拦截（toast「访客视图不可操作」） |

- 账户下拉包含：账户信息头（头像 + 名称 + 登录方式/邮箱 + 地址行）、我的资产、创作管理、观看历史、Logout。
- 「复制」写剪贴板并 toast「钱包地址已复制」；不支持剪贴板时提示手动选择。

## 4. 退出登录

- 入口：① 顶栏账户胶囊下拉 → `Disconnect`（直接退出，无需整页刷新）；② 含 `.auth-container` 的页面（首页/推荐/个人中心等）账户下拉 → `Logout` → 二次确认弹窗（取消 / 确定）。两条入口都回到同一未登录状态。
- 行为：清除 `storyfun_user` 登录态、关闭下拉、重渲染账户面（含顶栏）、toast「已退出登录」、派发 `auth-ready`；**刷新后仍为未登录**（新访客默认状态即未登录，不会自动回到已登录）。
- 退出**不改变**地址派生规则：同一账号再次登录仍得到同一地址。

---

## 5. 演示口径

- 验证码固定为 `123456`，弹窗内以灰色小字明示「演示环境」。
- 社交授权与钱包签名均为模拟：无真实 OAuth、无真实签名、无链上交易；钱包签名弹窗明示不产生交易与费用。
- 登录成功后派发 `auth-ready`，各页面据此重渲染（顶栏、资产页、创建页、币详情均监听该事件）。

## 6. 异常与边界

| 场景 | 行为 |
|---|---|
| 邮箱格式非法 | 行内红字，停留在第一步 |
| 验证码位数不足 / 错误 | 行内红字，停留在第二步；按钮可再次提交 |
| 反复点击发送 / 验证 | busy 期间按钮禁用，避免重复提交 |
| 重发倒计时未结束 | 重发按钮禁用并显示剩余秒数 |
| 关闭弹窗 | 清理倒计时；再次打开回到第一步（重置输入与错误） |
| 钱包签名被拒绝 | 保持在未登录态并 toast，不写入任何登录信息 |
| `localStorage` 不可用（隐私模式） | 登录态仅当前会话生效；地址派生不受影响 |
| 历史存档中的旧 `authMethod` | 读取时按未知值兜底为「邮箱登录」标签，不破坏已登录态 |

- [ ] 未登录时顶栏显示「登录 / 注册」，点击弹出登录弹窗（不再直接连接钱包）

- [ ] 邮箱两步：非法邮箱拦截；验证码错误行内报错且不登录；正确则登录成功并 toast「已创建内嵌钱包」
- [ ] 重发按钮 60 秒倒计时与文案正确，倒计时结束可重发

- [ ] 登录后顶栏为「头像 + 脱敏地址」，下拉含登录方式、邮箱（邮箱登录时）与地址复制
